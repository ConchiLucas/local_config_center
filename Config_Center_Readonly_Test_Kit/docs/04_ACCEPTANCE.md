# 04 · 实施阶段与验收

## 实施阶段

阶段 A：把只读布局接到用户现有数据库。确认一级/二级动态切换、每条配置有稳定 ID、没有秘密泄露、页面没有新增保存等入口。不必先接任何生成服务。

阶段 B：对话与图片真实闭环。实现一条配置的真实测试，记录版本、运行状态与输出。对话验证实际流式和完整模式；图片验证真实返回图的预览与放大。演示素材必须彻底与真实模式分离。

阶段 C：TTS 和视频。验证真正音频可播放，真正视频任务可追踪；实现媒体格式/鉴权/Range/过期地址处理。禁止只在日志里打印模型返回 URL。

阶段 D：数据库和 MinIO 只读探针。无任意 SQL、无任意目标 URL、无自动对象写入和删除。

阶段 E：长任务恢复、权限、异常、取消和真实浏览器兼容验证。按实际项目需要决定是否保存运行历史，不为历史功能增加一整套管理导航。

## 需要从现有项目读取或向用户确认的资料

先检查代码仓库已有内容，不重复向用户索取已经配置的信息。确实缺少时，明确列出数据库引擎/表映射、后端框架、现有密钥管理方式、供应商的真实网关协议、每类可用模型、存储访问策略和测试网络环境。

真实密钥通过安全环境配置，不让用户贴进页面，不写进样例 JSON、前端源码、测试报告或文档。

## 验收清单

1. 顶部一级导航、左侧二级导航都来自数据；Grok 与本地服务能呈现不同子菜单。
2. 配置主区没有编辑表单；只有真实详情和测试入口；没有新增、编辑、删除、保存、重置、高级选项、搜索、登录、头像和通知。
3. 一个二级目录可以有多个配置实例，测试准确绑定对应 ID 和版本。
4. 详情字段分类型；数据库没有 model/voice/quality，文本模型没有图片 HD 配置。
5. 测试打开一次就是大工作台；不经过第二个详情弹窗；可全屏和键盘关闭。
6. 输入修改仅影响本次测试；配置库没有任何写操作。
7. 对话流式是真实增量事件，不是拿到全部内容后再伪装打字。一次性在完成后显示。JSON 的包装协议与模型内容不混淆。
8. 图片直接展示，尺寸来自实际文件；点击能放大，不只显示地址。
9. TTS 的音频内容与输入一致，直接播放、暂停、拖动；真实输出与样例录音绝不混淆。
10. 视频可追踪任务和播放；拖动 Range、正确 MIME、失败和地址过期提示都验证。
11. 关闭再打开保留运行；生产需要刷新恢复时可根据 runId 查询。播放不在后台偷偷持续。
12. 上游不支持取消时不显示“已取消”；再次执行不会误造成重复计费。
13. 数据库测试真实检查连接，但只有受控只读探针；MinIO 只读操作且按对象类型预览。
14. 普通账号只看到获授权配置及结果；无 UI 登录入口不意味着无后端授权。
15. API 不返回明文秘密；错误与日志不带密钥；媒体代理不能拿任意 URL 抓取内网。
16. 空配置、未支持类型、无输出、超时、失败、取消、资源过期都可理解；不出现伪造“在线”“连接成功”“验证成功”。
17. 在用户实际使用的浏览器验证，至少覆盖其桌面环境；原型的 Chromium 检查不能代替 Safari 等浏览器验收。

## 本包现状

自动化检查覆盖：菜单、只读 DOM、三种对话演示、JSON 树/源码、图片放大和恢复、WAV/MP4 播放、侧栏展开、数据库/存储专用结果、错误与停止、390px 手机布局、只读 API、媒体 Range。

受运行环境浏览器 URL 策略限制，界面检查通过自包含 HTML 注入 Chromium 完成；SQLite 只读 HTTP API 使用 Python HTTP 客户端单独验证。没有宣称完成浏览器到真实服务器的全链路兼容验证。

实际检查明细见 TEST_REPORT.json。真实供应商、用户数据库和用户 MinIO 均未测试。
