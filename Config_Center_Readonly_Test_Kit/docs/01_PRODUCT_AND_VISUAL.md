# 01 · 产品结构与视觉方案

## 产品定位

“只读配置目录 + 能力验证工作台”。界面负责看清配置和验证效果；数据库及已有管理流程负责维护配置。不是增加一个新的可视化配置后台。

## 导航

一级导航在顶部，表示可配置资源分组，例如 Antigravity Tool、Grok、本地服务、MinIO。它们的名称、顺序、启用状态来自数据库查询结果。分组过多时顶部横向滚动或收进“更多分组”，但不提供“新增分组”。

二级导航在左侧，随一级分组替换。供应商可包含对话、图片、TTS、视频；本地服务可包含 PostgreSQL、Redis；MinIO 可包含对象存储、媒体访问。不要给所有分组强制塞入三个相同菜单。不支持的类型不注册；仅“尚未配置”的注册项展示空态，不编造连接状态。

三个层次要分清：group 是分组，page 是能力或服务目录，config 是一条配置实例。一个图片目录可以有多条图片配置，每条都能单独测试。一级导航不必叫 provider，以免无法容纳基础设施。

实际路由建议：`/config/:groupId/:pageId`，测试工作台可用查询参数 `?config=:configId&run=:runId`。原型使用 hash 路由方便本地打开；生产环境不必照搬。

## 只读主区

页面依次是：面包屑、当前二级标题、一句用途说明、配置条目。每条条目包含名称、类型标识、真实配置摘要、连接/验证状态和一个测试入口。

不要有显示成 input 的 API Key、可点击开关、保存、重置或高级选项。使用 `<dl>` 或等效语义的键值组件。长端点可换行，不撑破布局。

模型信息不等于连接状态：配置存在只能写“已登记”或“未验证”；后端真正测试过才能给“最近验证通过”。版本变化后，旧验证要标为旧版本结果。

密钥只显示“已配置 / 未配置 / 不适用”。可在确有必要时提供服务端生成的掩码，但绝不把完整密钥发给前端后再遮挡，也不提供眼睛按钮。

## 详情按类型设计

| 类型 | 详情内容 | 视觉摘要 |
| --- | --- | --- |
| 对话 | 模型、端点、协议、超时、输出限制、真实能力 | 返回方式简述；没有图片质量 HD 等错误字段 |
| 图片 | 模型、画幅、尺寸、输出格式、是否支持参考图 | 画幅框和输出说明 |
| TTS | 模型、默认音色、语言、格式、采样信息 | 简洁音频视觉，但装饰波形不能冒充真实分析 |
| 视频 | 模型、时长、画幅、任务方式、返回格式 | 视频画幅与任务提示 |
| 数据库 | 引擎、主机、端口、库名、用户、TLS、超时 | 连接路径与只读探针说明 |
| 存储 | endpoint、bucket、region、访问方式、凭据状态 | 对象类型与可预览媒体 |

无关字段直接不存在，不是折叠到高级选项。能力由实际模型/适配器确认，不靠前端的一个开关“启用支持”。

## 视觉

保留深海蓝和青绿色方向，但不沿用上一张效果图的高亮边框、广告语卡、夸张模型水晶和大面积荧光。新方案更接近克制的产品控制台。

颜色来自 `web/styles.css`：背景 `#080f1b`，面板 `#101b2c`，主要文字 `#e9f1fb`，次要文字 `#91a1b7`，主强调 `#70e4d0`。这些是本设计的选择，不是某个厂商官方规范。

顶部约 78px，桌面侧栏约 244px。主要标题 30px，正文约 12–14px，卡片内距 24–28px，圆角约 18px。注意真正的字段内容不能低对比；极低对比只能用于装饰性英文眉题等次要内容。

背景素材放在最底层，叠加深色渐变并降低可见度。表单/详情面板必须有足够实色底，不把正文直接压在发光纹理上。不要把整个 UI 效果图切成图片当网页，也不要从效果图截图出一个假的输入框。

字体使用系统字体回退；本包不分发字体文件。所有文字、图标、控件是可选中、可交互的真实页面元素。

低于 640px 时，二级菜单改为紧凑横向条；测试工作台占满宽度，输入和结果上下排列。尊重 reduced-motion，焦点可见，键盘可操作。
